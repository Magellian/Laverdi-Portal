# 2026-04-25 — LaVerdi Signup Flow Debugging (19:00-20:00 UTC)

## CRITICAL BUG FOUND & PARTIALLY FIXED

### Issue #1: Signup Request Hang (FIXED ✅)
**Root Cause:** `await sendWelcomeEmail()` in `/pages/api/auth/create-profile.ts` was blocking the entire request. If SendGrid API was slow or timed out, the response would never be sent, causing "Invalid JSON" on frontend.

**Fix Applied:**
- Changed from `await sendWelcomeEmail()` to fire-and-forget pattern
- Added 10-second timeout to SendGrid fetch calls in `/lib/email.ts`
- Signup now returns instantly after database insert
- Email sends asynchronously in background

**Status:** ✅ Deployed and verified working

### Issue #2: RLS Blocking Profile Creation (CURRENT BLOCKER ❌)
**Current Error:** When user signs up, they get:
```
Failed to set up your account: duplicate key value violates unique constraint "users_email_key"
```

**Root Cause:** Row Level Security (RLS) policy on `public.users` table is blocking INSERT operations, even though `createAdminClient()` uses the Supabase service role key (which should bypass RLS).

**Why It's Confusing:**
- Auth account gets created successfully (bypasses RLS)
- `create-profile` tries to insert profile into `public.users` 
- RLS policy denies the insert
- Frontend receives confusing "duplicate key" error (not the actual RLS denial)

**What Was Verified:**
- Service role key IS in docker-compose environment variable definition
- But `docker exec` shows it as empty/escaped (`\`) — likely shell escaping issue
- Supabase client code looks correct (uses `createClient()` with service role key)
- Profile table schema is correct

**Next Steps to Debug:**
1. Check portal logs with debug logging:
   ```bash
   docker logs laverdi-portal 2>&1 | grep CreateProfile
   ```
2. Look for RLS error code (likely `PGRST` error)
3. Options to fix:
   - Temporarily disable RLS on `users` table to test flow
   - Fix the RLS policy to allow service role inserts (should already work)
   - Fix env var escaping on VPS so service role key loads correctly
