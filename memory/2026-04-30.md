## ✅ Durable Architecture (PROVEN)

### Message Bridge (File-Based, Operational)
- **Hermes outbox:** `outbox_hermes/` → Crawford reads JSON messages
- **Crawford outbox:** `outbox_crawford/` → Hermes reads JSON responses
- **Polling interval:** 0.5 seconds per agent
- **Message format:** `{"timestamp": "ISO-8601", "sender": "hermes", "action": "...", "payload": {...}}`
- **Auth:** All requests include `"secret": "hermes-command-secret-2026-04-30"`
- **Status:** ✅ Tested end-to-end, working reliably

### API Specification (4 Commands)
1. **`system:info`** → Hermes returns instance metadata (status, version, uptime)
2. **`system:restart`** → Hermes restarts OpenClaw gateway
3. **`provision:check`** → Hermes reports provisioning queue + status
4. **`exec:command`** → Hermes executes shell command, returns stdout/stderr/exit code

### Response Contract
```json
{
  "timestamp": "ISO-8601",
  "sender": "hermes",
  "action": "...",
  "status": "ok|error",
  "data": {...},
  "error": "message if status=error"
}
```

## ❌ HTTP Server Attempts (All Failed)

**Root cause:** Windows 10 + Python 3.12 + Werkzeug cannot dispatch HTTP requests. Tried:
- Flask (Werkzeug backend) — hung on POST
- Python `BaseHTTPServer` — hung on dispatch
- Raw sockets + manual HTTP parsing — protocol errors
- Waitress (pure Python WSGI) — hung on request
- Node.js Express — worked in theory, but process management issues
- Bare Flask with debug=False — still hung

**Why it matters:** HTTP is fragile in this Windows environment. File bridge avoids the issue entirely.

## 🔐 Security Notes

- **Shared secret:** Store in `.env.local` on both servers (REDACTED in docs)
- **File permissions:** Crawford & Hermes need RW access to shared `outbox_*` directories
- **No external HTTP exposure:** File bridge only works locally (same VPS or SMB mounts)
- **Message signing:** Not implemented yet (consider adding HMAC-SHA256 if untrusted networks)
