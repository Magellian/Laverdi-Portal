### What Was Accomplished

**1. Fixed Gateway Startup Race Condition (CRITICAL FIX)**
- **Problem:** Command Center v1 created container, waited for config dir, injected config via `docker cp`, then restarted. Gateway would sometimes hang on restart or crash loop.
- **Root cause:** Gateway wrote its own config on first boot → Command Center overwrote it → restart caused "Config overwrite" collision → gateway stuck at "starting..."
- **Fix:** Command Center v2 — pre-creates user data directory on HOST filesystem with `openclaw.json` already written, then volume-mounts it into container. Gateway boots with correct config from first second. Zero restarts needed.
- **Result:** Clean first-boot in ~7-14 seconds every time.

**2. Fixed Bonjour Crash Loop (CRITICAL FIX)**
- **Problem:** Bonjour/mDNS plugin tries to probe network on startup. In Docker containers (no multicast), probing times out after ~10-20s → unhandled promise rejection → gateway crashes → restarts → crash loop forever.
- **Fix:** Disabled `bonjour` and `phone-control` plugins in the provisioned config. These are unnecessary in a server/Docker context.
- **Result:** Gateway starts cleanly with 4 plugins: acpx, browser, device-pair, talk-voice.

### Key Technical Decisions
- **Apps available to all tiers** — companion app + browser extension are access methods, not premium features. More surfaces = more token burn = more upgrades.
- **Secrets in .env only** — Git repo has REDACTED placeholders. Real keys live in `.env.local` on server and container env vars.
- **bind: "lan"** works in Docker containers (OpenClaw resolves it to 0.0.0.0 inside container). Don't use `bind: "0.0.0.0"` directly — it works but triggers a security warning.
