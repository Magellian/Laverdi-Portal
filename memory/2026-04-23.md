## Current Problem: Payment → Upgrade Flow Broken
**Issue:** After completing Stripe payment, user tier doesn't update and container doesn't provision.

**Root Cause Found (2026-04-23 21:35):**
- Stripe is NOT redirecting to `/checkout/success?session_id=...` after payment
- Instead user gets sent to `/auth/login?message=payment-successful` 
- This means the success page never runs
- The confirm-upgrade endpoint is never called

**Why It's Happening:**
- Likely: User is logged OUT during Stripe checkout
- Stripe creates session while unauthenticated
- On return, app sees no session and redirects to login before success page can run
- session_id never makes it to the URL because the redirect happens too early

## Solutions Attempted
1. ❌ Stripe webhooks: Can't reach portal (HTTPS/firewall issue)
2. ❌ Success page workaround: Needs session_id in URL but Stripe isn't passing it
3. 🔄 Fixed confirm-upgrade to get email from Stripe instead of requiring logged-in session
4. 🔄 Still need to test while staying LOGGED IN through entire checkout flow
